# Data reliability: the 14 rules and the tests that enforce them

The platform's value depends on never presenting a guess as a fact. Each rule below is enforced in code (not by convention) and
covered by automated tests. Test references are `file › test name`; run them all with `npm test`.

Every significant insight also carries `evidence[]` (observation, offer, match or site records with URL and time) and a
`scoreBreakdown`; `reports.test.ts › every insight is ranked, scored transparently and traceable to evidence` and
`evidence ids and URLs resolve to retained evidence rows` check that those references resolve.

| # | Rule | How it is enforced | Tests |
| --- | --- | --- | --- |
| 1 | **Unknown stock is never stored as in stock** | `classifyStock` returns `unknown` unless the page states availability; the stock state machine ignores `unknown` for transitions and never raises an alert from it. | `core/domain.test.ts › never turns unknown availability into in_stock`; `connectors/extract.test.ts › keeps a missing price as null — never 0 — and an unknown availability as unknown`; `e2e/stock-alerts.test.ts › untracked inventory is unknown, not zero, and raises no alert` |
| 2 | **Unknown shipping cost is not zero** | Shipping is `null` unless published; "free shipping" is an explicit 0. | `connectors/extract.test.ts › keeps shipping unknown unless explicitly published (free shipping is an explicit 0)` |
| 3 | **Missing prices are not converted to zero** | Price parsing returns `null`; currency conversion and comparison skip `null`; exports print blank, not 0. | `core/parsing.test.ts › never turns missing prices into zero`; `core/parsing.test.ts › never assumes a rate for unknown currencies` |
| 4 | **Blocked and failed collections are distinguishable from an empty catalogue** | Profiler statuses Blocked/Failed are distinct from a catalogue of 0; a scan that extracts nothing is `failed`, not `succeeded`; robots 5xx is `Failed`, 401/403/429 is closed. UI shows "not collected (blocked)" instead of "no match". | `connectors/connectors.test.ts › HTTP 500 → Failed (a technical error), never an empty catalogue`, `robots.txt that disallows everything → Blocked…`, `bot-protection challenge → Blocked…`, `login-gated site → Blocked…`; `paginates and resumes from a cursor; a mid-catalogue failure surfaces as an error, not an empty catalogue`; `e2e/pipeline.test.ts › collects every supported site, and reports blocked / failed sites as such (never as empty catalogues)` |
| 5 | **Stale observations are not described as fresh** | Every observation has a time; anything older than the freshness window (default 36 h) is flagged `stale` and rendered with a dashed border and "stale" label; reports list stale counts. | `core/parsing.test.ts › flags stale observations rather than calling them fresh`; `e2e/reports.test.ts › coverage rows disclose partial catalogues and freshness instead of hiding them` |
| 6 | **Product similarity does not prove identity** | Identical requires brand + size (or GTIN / brand+MPN). Name-only identical is capped at 0.9 and goes to review unless size is verified; different brands are never identical; AI adjudication can only suggest. | `core/domain.test.ts › NEVER labels products from different brands as identical, however similar the names`, `does not call name-only matches identical when size cannot be verified`, `AI adjudication can never upgrade to identical over hard conflicts and is never auto-accepted`; `e2e/pipeline.test.ts › never calls products from different brands identical` |
| 7 | **Apparent discounts are not automatically historically verified** | `verifyDiscount` returns `verified` only with enough price history agreeing; otherwise `unverified` / `insufficient_history` / `contradicted`. | `core/domain.test.ts › is unverified with no history and never claims historical validity`, `is unverified when the offer does not state both prices` |
| 8 | **A social post does not prove a paid campaign** | `paidStatus` is the literal type `'not_determined'`; copy says "observed, not proven paid". | `e2e/pipeline.test.ts › records observed marketing content without calling it a paid campaign` |
| 9 | **AI numeric facts are validated against evidence** | `findUnsupportedNumbers` rejects any number in an AI summary that is not in the computed facts/KPIs; extraction results must be backed by text present on the page; page text is wrapped as untrusted data. The core app works with no AI. | `core/domain.test.ts › flags numbers in a summary that do not come from records`, `wraps untrusted content and strips fake delimiters`; `e2e/reports.test.ts › discards an AI summary that contains numbers not found in the records`, `keeps a summary whose numbers all come from computed facts`, `works with no AI provider at all` |
| 10 | **Partial catalogue coverage is disclosed** | Per-site coverage (collected vs estimated, complete flag, warnings) in the dashboard honesty bar, data-quality page, reports, PDF/Excel summaries; a partial report is labelled partial with the reason. | `e2e/reports.test.ts › coverage rows disclose partial catalogues…`, `is saved as a partial report because a competitor could not be collected, and says why`; `e2e/scheduler.test.ts › publishes a clearly labelled partial report at 08:50 when one site has not run` |
| 11 | **Observations keep source URL and time** | `price_observations` / `stock_observations` rows carry `source_url`, `observed_at`, method and evidence id, and are append-only (database triggers reject UPDATE/DELETE). | `e2e/pipeline.test.ts › stores products, variants and append-only observations with provenance and fixture flags`; `integration/database.test.ts › observations are append-only` |
| 12 | **Alert transitions are deduplicated** | Alerts are keyed `type:variant:episode`; re-evaluating the same transition produces the same key (unique index); a transient `unknown` does not reset state; sync is idempotent. | `core/domain.test.ts › alerts when crossing from above the threshold to the threshold, and only once`, `goes low -> out -> restocked, then a later drop is a NEW episode…`, `the same transition evaluated twice from the same memory yields the same dedupe key`, `a transient unknown observation does not cause duplicate alerts`; `e2e/stock-alerts.test.ts › alerts once when an item goes out of stock, not again while unchanged…`, `syncing the same inventory twice is idempotent (no duplicate alerts)`, `a competitor going out of stock never raises a customer alert` |
| 13 | **A report snapshot is consistent across dashboard and exports** | A published report is one immutable JSON document (stable hash; a database trigger blocks changes). Dashboard views, PDF, CSV and Excel render only from it. | `e2e/reports.test.ts › is immutable and hash-stable…`, `keeps headline numbers consistent with the underlying rows`, `CSV: one row per source×competitor comparison, with the same numbers as the snapshot`, `Excel: the comparison sheet has the same rows…`, `PDF: opens, is labelled partial/fixture, and shows the same headline numbers`; `e2e/api.test.ts › downloads PDF, CSV and Excel with correct headers and consistent content`; `integration/database.test.ts › published report snapshots are immutable but drafts can be completed` |
| 14 | **One customer cannot access another customer's private data** | PostgreSQL row-level security enabled **and forced** on every tenant table, bound per transaction; the API role has no `BYPASSRLS`; every org route checks membership and answers 404; ids from another workspace never resolve. | `integration/database.test.ts › enables AND forces row-level security with a policy on every tenant table…`, `a tenant only sees its own rows`, `fails closed when no tenant is bound`, `cannot read another tenant row even when filtering for it explicitly`, `rejects inserting a row for a different tenant`, `cannot update or delete another tenant rows`, `cannot move a row to another tenant via UPDATE`, `isolates child tables…`, `rejects a malformed tenant id…`; `integration/queue.test.ts › the API role can enqueue but still cannot read tenant data`; `e2e/api.test.ts › another signed-in user gets 404 for EVERY resource of this workspace, and cannot cross-reference ids` |

## Related safeguards that are tested

- **SSRF**: `connectors/safe-fetch.test.ts` (private, loopback, link-local, metadata, IPv4-mapped/NAT64, DNS rebinding with mixed
  records, redirect re-validation, ports), `connectors/connectors.test.ts › refuses private/internal targets without making any request`.
- **Politeness**: robots.txt obeyed, missing robots means no restrictions, repeated denials stop collection
  (`safe-fetch.test.ts › obeys robots.txt…`, `stops hitting a host after repeated access denials and never retries a denial`).
- **Auth/session**: `e2e/api.test.ts` — HttpOnly cookies, CSRF header + origin check, generic wrong-password answers, lock-out,
  rate limits, single-use reset tokens with session revocation, Shopify webhook HMAC.
- **Secrets**: AES-256-GCM key ring with rotation and tamper detection (`core/domain.test.ts › encrypts secrets with key rotation support and detects tampering`);
  redaction of secrets from logs.
- **Authorised-quantity conflicts**: when an authorised inventory quantity and the public page disagree, the stock view flags
  "page and inventory disagree" instead of silently picking one.

## What these tests do not prove

They run against fixture websites and a real PostgreSQL, not against live competitor sites, real email servers or
third-party APIs. See [limitations.md](limitations.md) and [verification-report.md](verification-report.md).
